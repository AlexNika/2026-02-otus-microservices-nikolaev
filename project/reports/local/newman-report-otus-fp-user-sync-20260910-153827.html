Collection Description
E2E сценарий асинхронной репликации контактных данных пользователя (USER -> NOTIFICATION, DELIVERY): 1. Регистрация пользователя с phone и 2 адресами доставки -> 201. В одной транзакции в общий outbox записываются UserCreatedEvent (USER -> BILLING) и UserSyncEvent (полный снимок контактов и адресов). 2. Логин -> JWT. 3. GET /api/v1/profile - телефон и адреса с созданными id. 4. PUT /api/v1/profile (Bearer) - смена phone, обновление адреса #1 (isDefault=false), удаление адреса #2, добавление нового адреса без id. Публикуется новый UserSyncEvent. 5. Проверки read-моделей через внутренние эндпоинты (заголовок X-Internal-API-Key): GET {{notificationServiceUrl}}/internal/contacts/user/{{userId}} и GET {{deliveryServiceUrl}}/internal/delivery/user-addresses/{{userId}}. 6. Повторный PUT с тем же телом (имитация повторной доставки на уровне API) -> read-модели без изменений и без дублей (идемпотентность: NOTIFICATION - processed_messages + PK user_id, DELIVERY - upsert по (user_id, source_address_id) + delete-not-in). Запуск: newman run postman/local/otus-fp-user-sync.postman_collection.json -e postman/local/local.postman_environment.json --env-var internalApiKey=<ключ из fp/.env>. Предпосылки: поднята инфраструктура DEV/docker-compose.yaml (6x PostgreSQL + RabbitMQ); запущены USERService (со SPRING_FLYWAY_ENABLED=true, иначе миграция V6 не накатится), NOTIFICATIONService и DELIVERYService с переменными из fp/.env. USER -> BILLING канал работает: outbox-планировщик публикует USER_CREATED в users.events и USER_SYNC в user.sync.events (цикл ~1 c). Ручные SQL-проверки (pgAdmin/psql): -- 1) Outbox: события USER_SYNC публикуются (event_type='USER_SYNC') SELECT id, event_id, event_type, status, attempts, created_at, sent_at FROM user_outbox WHERE event_type = 'USER_SYNC' ORDER BY id; -- 2) NOTIFICATION read-модель: ровно одна строка на пользователя SELECT user_id, email, phone, updated_at FROM notification_contacts WHERE user_id = <userId>; -- 3) DELIVERY read-модель: адреса без дублей (UNIQUE(user_id, source_address_id)) SELECT user_id, source_address_id, full_address, city, postal_code, is_default, updated_at FROM delivery_user_addresses WHERE user_id = <userId> ORDER BY source_address_id;
